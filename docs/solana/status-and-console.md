# 等待队列、状态图标与 Windows 日志修复（0.4.7+10）

- 截止日期开关仅在“限时活动”分类的 10 个任务设置中提供，其他设置页不显示；分类来自后端菜单，配置存储格式兼容原版本。
- 等待任务按下次运行时间从早到晚显示，包括左侧等待列表、调度中心等待条件和总览候选目标。相同时间保持稳定顺序；无效或缺失时间放到最后。显示排序不会改变实际可执行队列的调度优先级。
- 配置执行器在运行或等待下一任务时统一使用圆形暂停图标。未启动和暂停状态使用圆形播放图标；异常使用感叹号图标。
- 调度器圆点与左侧配置图标使用同一状态来源：运行绿色、暂停黄色、异常红色；未启动保留紫色，连接中断时显示灰色。

## OAS2 异常原因

2026-09-26 14:34 的异常为 `UnicodeEncodeError: 'gbk' codec can't encode character '\u2705'`。控制台尝试输出包含“✅”的日志时，Windows/Colorama 的 GBK 输出流拒绝了字符，异常传播到任务执行过程。

控制台现在优先配置 UTF-8，并停用 Rich 的旧 Windows 控制台渲染分支。遇到无法重新配置编码的宿主包装流，仅在控制台中转义其不支持的字符；文件日志和传给界面的日志仍保存原始 Unicode 内容。无需删掉任务日志里的表情字符。

验证覆盖：GBK 严格编码管道、不可重配的 Colorama 输出流，以及独立 Python 进程内真实 logger 的普通日志、直接打印和异常打印。界面回归覆盖等待时间顺序、时间相同时稳定、不同配置图标独立、状态圆点颜色同步及离线提示。

验证结果：后端 209 项通过，前端完整套件 164 项通过（1 项真实服务检查跳过），截止日期及中文覆盖追加回归 12 项通过，静态分析无问题。安装后读回接口确认普通任务不返回截止字段，限时活动保留该字段。
