## 构建与运行

后端使用项目原有 Python 3.10 环境和依赖，从仓库根目录启动：

```powershell
python server.py --host 127.0.0.1 --port 22288
```

Windows 客户端需要 Flutter 3.35 或以上版本及 Visual Studio 的桌面 C++ 构建组件：

```powershell
cd oasx
flutter pub get
flutter build windows --release
```

发布目录为 `oasx/build/windows/x64/runner/Release`。exe、DLL 与 data 必须一起分发。在客户端连接设置中填写自己的后端地址。升级前停止任务，备份原客户端、后端代码、`config/` 与 `runtime_data/`，再替换代码；不要用开发配置覆盖用户配置。

## 执行与异常处理

- 电源按钮：未启动时启动；正常运行时立即结束脚本、交还游戏操作；异常时重新运行。右上角停止按钮同样立即停止。旁边的暂停／继续按钮等当前任务段结束后保留进程与进度。
- 重新运行会先结束旧执行器并确认退出，将旧未完成运行记为中断，然后按已保存的计划启动新进程。旧运行不会被标记为成功，也不会重放未确认的步骤。
- 状态版本过期表示请求尚未执行，界面刷新后可再次手动点击，不再锁住启动。网络中断或记录未保存等未知结果仍需要核验，避免重复操作。
- 闪电按钮将已启用的待执行任务安排为立即到期；复制按钮复制当前任务的原始非脱敏 JSON。

## 调度策略

- **原有策略**：使用原来的任务顺序。
- **公平调度·试算**：显示公平调度会怎样选择，实际执行仍采用原策略。
- **公平调度**：在可执行任务中按执行份额和虚拟截止时间选择，在任务支持的安全位置切换；无法分批的任务完整运行后再交还设备。

登录准备成功后重新选择任务，不消耗故障恢复次数。不可分割的长恢复任务可在完整预算窗口获准执行一次，之后按实际占用记账；连续恢复失败受次数和退避约束，耗尽后停止并提示。等待时间保护不绕过恢复限制。任务权重兼容配置键和任务命令名称。

本机组队只向最终实际选中的任务发送请求；有效的双方约定任务优先等齐，不抢占正在执行的设备租约。任务无法执行时会退避等待，保持安全停止响应。

## 真八岐大蛇本机联动

在双方“全局配置 → 本机组队同步”中启用联动、互填队友配置名，并打开“真八岐大蛇联动”。该新开关默认关闭。双方的真蛇任务仍需启用，原有初始队长／队员、不同模拟器和好友邀请设置需要正确配置。

调度器等齐双方后进入已有的真蛇逐轮握手、队长轮换及奖励确认。就绪等待有超时和重试间隔，等待时可以安全停止；不会代替用户修改组队角色或好友信息。

## 指标与记录

当前菜单 55 个可执行任务全部接入生命周期指标。其中 19 个任务提供已有的细分计数，其余使用 `0/1 项`，只有任务明确成功才完成。35 个战斗任务统计实际观测的结算，20 个非战斗任务显示“不涉及战斗”；历史未采集数据保持未知。详见 [逐项覆盖及口径](task-metrics.md)。

统计与审计使用本地有容量上限的文件存储，不需要部署数据库。普通历史按保留策略清理，未结束运行及必要恢复状态单独保留。不要直接删除 `runtime_data/` 来解除异常。
