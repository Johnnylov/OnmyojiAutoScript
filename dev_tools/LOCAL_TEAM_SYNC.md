# 本机双配置组队联动

当前支持八岐大蛇（Orochi）和契灵（BondlingFairyland）。真八岐大蛇不参与本次联动，正在运行真蛇或登录恢复时会等待该任务结束。

## 使用

重启 OAS 后端，再启动 oas1 和 oas2。两份配置都必须处于运行状态，并操作不同的游戏窗口/模拟器；手动停止的配置不会被自动启动。

在全局游戏设置的「本机组队联动」中，两边启用联动并相互填写配置名：oas1 填 oas2，oas2 填 oas1。八岐大蛇和契灵可分别开关。其他配置默认关闭此功能。

配置示例（每台机器需自行启用，账号配置不会随代码发布）：

```json
{
  "enable": true,
  "partner_config": "对方配置名",
  "sync_orochi": true,
  "sync_bondling": true,
  "ready_timeout": 600
}
```

实际位置为 `global_game.local_team`。角色、好友名单、御魂、次数和原调度时间不由联动模块修改。八岐大蛇需使用相同层数并配成 leader/member；契灵需使用相同模式、契灵种类，并配成 leader/member 或 handoff1/handoff2。双方对应任务须启用。

## 运行行为

- 任意一边的组队任务被调度到，向对方发送本机请求，优先选中同一任务。无需对齐两边的下一次运行时间，也无需 MQTT 服务。
- 空闲时约每秒检查请求；执行任务时在截图检查点响应。战斗、结算和未知页面继续原流程，确认回到可导航页面或组队房间后再切换。登录恢复、真蛇与已配置的休息窗口会正常完成。
- 双方完成御魂切换等准备后互相确认，再启动邀请等待。就绪等待默认最多 10 分钟，可设置为 30～1800 秒；等待时间不计入刷取时长。
- 两边同时触发不同任务时，以共享文件锁下最先建立的请求为准，不会互相覆盖或循环切换。一个轮次结束后才开启下一轮。
- 队友停止、重启或超时会使本轮请求失效，未完成的组队任务在两分钟后重试。若某一边因契忆上限等正常跳过，另一边跟随其下次运行时间结束等待。
- 被临时让出的任务保留原调度，不记为完成或失败。组队结束后重新进入原调度；原任务从自身入口重新运行，不保证恢复到原局数或原点击步骤。

日志可搜索「本机组队联动」。运行状态存放在 `log/.local_team.json`，使用文件锁、原子写入、进程实例标识和心跳处理并发及失效请求，不写对方的配置文件。进程停止后残留的旧请求不会被新进程继续执行。

旧后端已经加载的配置模型不会识别新字段，因此请在重启到新后端后再修改联动设置，避免旧进程保存配置时丢失这些字段。关闭双方的联动开关即可恢复各自调度。

## 验证

`dev_tools/test_local_team_sync.py` 覆盖独立进程同时触发、双向唤起、就绪等待、停止/重启、关闭任务、跳过、调度优先级及战斗/结算期间禁止切换。使用临时配置与模拟设备，不操作实际游戏。

```powershell
toolkit\python.exe -m unittest discover -s dev_tools -p test_local_team_sync.py -v
```
